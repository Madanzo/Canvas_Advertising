## Proposed order, each release requiring separate approval

1. **Legacy stop gate:** if the legacy export is still deployed, apply its small handler overlay to verified current source and target only `syncLeadToCRM`. Keep both `CRM_LEAD_ADAPTER_ENABLED` and the additional legacy-specific `CRM_LEGACY_FORWARDING_ENABLED` unset/false. Tests prove no URL/key/configuration, snapshot or network access when disabled. Do not provision either enable flag. This fix can be reviewed/released independently of quote UX and SMS. Retire this handler when the newer adapter replaces the same export; never register both.
2. **SMS safeguards before new quote Hosting:** prepare a verified current-source overlay of the consent module and the three edited helpers. Include every deployed function calling them: `onNewLead`, `processBulkCampaign`, `calcomWebhook`, `processWorkflowQueue`, and `sendDirectMessage`. Verify caller inventory again against current source. Preserve all provider/client/runtime settings and the missing queue index. The queue remains blocked; consent checks do not authorize history or restore queue operation. Existing workflow instances without the new explicit enrollment grant fail closed for SMS. Email/task behavior is unchanged; SMS skips are logged as skipped, never delivered. A separate historical-exclusion policy is still required before any general queue restoration.
3. **Disabled adapter compatibility, separately from Hosting:** after the CRM owner confirms the ten canonical IDs/persisted tenant mapping, incorporate PR #4's canonical aliases and productionRequest consent mapping into the newer adapter release. Keep intake, general forwarding and test-only forwarding disabled. Preserve immutable serializedBody and idempotency keys and exclude held history. The newer adapter replaces the legacy `syncLeadToCRM`; do not apply the legacy wrapper to it. Existing outbox records must not be rewritten to add product details. Typed CRM product/upload ingestion remains a future schema extension; Canvas stores structured details and the current CRM message carries reviewed summary text.
4. **Hosting-only quote rollout:** after the consent safeguard review/verification and adapter mapping review, approve only `quote.html`, `quote-es.html`, `css/styles.css`, `js/main.js`. Keep `js/firebase-config.js` byte-identical to the deployed App Check fix. Stage only the scoped quote additions against current live CSS/JS using the hash-checked overlay tool; compare the full live manifest/configuration before releasing. Do not include Functions, rules, indexes, CRM code/configuration or other website work in this Hosting release. Hosting and adapter are separate release artifacts, even though PR #4 reviews their compatible payload mapping together.
5. **Recovery remains separate and unimplemented:** the previously proposed exact-two-record recovery runner is not part of any branch here. Its implementation/execution requires separate review; consent-policy deployment alone is not approval to bypass missing grants on old instances. Do not create the missing index, run broad queue handlers, resubmit records, or replay historical invocations. Normal notification restoration needs an explicit historical exclusion/authorization design before the index can safely become ready.

A freshly successful test run/CI at each final SHA is required; green workflows at the earlier `1829298` do not validate later UX commits. No new production verification submissions are included.
