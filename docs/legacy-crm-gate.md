# Disabled legacy CRM trigger draft

The deployed legacy v5 handler threw `functions.config() has been removed in firebase-functions v7` before its missing-URL exit. Its replacement handler now exits before configuration access, reading a lead, or network calls unless both explicit enable controls are the exact string true. The existing general `CRM_LEAD_ADAPTER_ENABLED` control and the additional `CRM_LEGACY_FORWARDING_ENABLED` control default false. No environment values, secrets or tenant settings are changed; no flags should be enabled in this rollout. The additional flag prevents a later general adapter rollout from incidentally enabling the legacy path.

The enabled-path code uses only environment parameters, not removed functions.config(), and preserves the legacy event payload. Its enabled branch is mock-tested solely for review and is not approved for production use or replay. It is not the newer immutable-outbox adapter and must be retired when that adapter replaces the export. No retry loop or historical processing is introduced.

Tracked main does not contain the deployed legacy export. The sibling App Check parent already contains the newer adapter under the same export name. To avoid replacing that newer handler, this draft supplies `functions/legacy-crm-trigger.js` and `tools/stage-legacy-crm-fix.cjs`: give it a verified current live index.js, its expected SHA-256, and an empty local output directory. It checks the legacy shape, replaces exactly that export with the module binding, copies the module, and preserves every other source byte. It never authenticates, connects, changes settings or deploys. Do not deploy this branch's whole functions/index.js.

Run `node --test functions/test/legacy-crm-trigger.test.js`. Tests use throwing spies to prove disabled/missing flags never touch configuration, snapshots or providers, even with an otherwise configured endpoint. See release-order.md for separate rollout order and dependencies.
